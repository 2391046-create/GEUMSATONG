# 원장(LEDGER) · 난이도 맞춤 금융 기사 리더

URL을 붙여넣으면 기사 본문을 가져와서, 내가 고른 금융 난이도(초급/중급/고급)에 맞춰
① 어려운 금융 용어를 자동으로 찾아 설명해주고,
② 기사 속 인과관계를 흐름도로 그려주고,
③ 기사에 등장한 기업을 DART(전자공시시스템)에서 조회해 재무 그래프·최근 공시로 보여주는
1인 프로젝트용 웹앱입니다.

## 구성

```
finance-reader/
  server.js              Express 서버 + API 라우트
  services/
    articleExtractor.js  URL → 기사 본문 추출 (cheerio)
    llm.js                Groq(무료) API 호출 (용어설명/흐름도/추천)
    dart.js                DART Open API 연동 (기업 재무/공시)
    store.js               읽은 기사 이력 저장 (data/readingHistory.json)
  public/                 프론트엔드 (순수 HTML/CSS/JS, 빌드 도구 없음)
    index.html
    style.css
    app.js
  data/                   런타임에 자동 생성되는 캐시/이력 파일
```

## 1. 필요한 것

- Node.js 18 이상
- **Groq API 키 (무료)** — https://console.groq.com 에서 신용카드 없이 발급 (용어 설명·흐름도·추천에 사용)
  1. 구글/깃허브 계정으로 가입
  2. 좌측 메뉴 **API Keys** → **Create API Key**
  3. `gsk_`로 시작하는 키 복사
  - 무료 한도: 분당 30회, 일 1,000회 정도 (모델별로 다름). 개인 프로젝트로 충분하고, 초과하면 잠깐 대기 후 자동 리셋됩니다.
- **DART Open API 키 (무료)** — https://opendart.fss.or.kr 에서 발급 (기업 재무/공시 조회에 사용). 발급 안 해도 나머지 기능(용어 설명, 흐름도, 추천, 핫기사)은 정상 작동하고, DART 버튼만 비활성화됩니다.

## 2. 설치 및 실행

```bash
cd finance-reader
npm install
cp .env.example .env
```

`.env` 파일을 열어 키를 채워주세요:

```
GROQ_API_KEY=gsk_...
GROQ_MODEL=llama-3.3-70b-versatile
DART_API_KEY=발급받은키
PORT=3000
```

서버 실행:

```bash
npm start
```

브라우저에서 `http://localhost:3000` 접속.

## 3. 사용 흐름

1. **Lv.01 난이도 선택** — 초급/중급/고급 중 선택 (localStorage에 저장되어 다음에 접속해도 유지)
2. **Lv.02 홈** — 기사 URL 붙여넣기 + 하단에 "AI 추천"(최근 읽은 기사 패턴 분석)과 "오늘의 핫 기사"(Google 뉴스 RSS) 표시
3. **Lv.03 기사 리더** — 본문 안 금융 용어에 점선 밑줄이 생기고, 마우스를 올리면 난이도에 맞춘 설명이 영수증 스타일 말풍선으로 뜸
   - **📈 기사 흐름 보기** — Claude가 기사에서 뽑아낸 원인→결과 관계를 SVG 흐름도로 표시
   - **🏛 DART 기업 정보** — 기사에 언급된 기업(복수면 드롭다운으로 선택)을 DART에서 조회해 최근 매출/영업이익/순이익 막대그래프와 최근 3개월 공시 목록 표시

## 3. 사용 흐름 (2026-07-18 개편)

1. **온보딩** — "평소 금융기사를 어떻게 읽으세요?" 중 하나를 고르면 난이도(초급/중급/고급)가 정해지고, 관심분야(주식·ETF, 금리·대출 등)를 선택하면 추천에 반영됩니다. "시작하기"를 누르면 저장됩니다.
2. **홈** — 상단 검색창에 기사 URL을 붙여넣거나, "기사 본문 직접 붙여넣기"로 텍스트를 바로 붙여넣어도 됩니다. 아래에는 "오늘의 추천 기사"(히어로 카드 1개 + 보조 카드 최대 3개, 관심분야/읽은 이력 기반, 실제 뉴스 링크)와 "나의 금융 이해도"(점수/레벨/이번주 통계/취약분야) 패널이 있습니다.
3. **기사 리더** — 원문 기사 그대로(제목, 기자명, 날짜, 대표사진, 문단 구조 유지)를 보여주고, 그 위에 난이도에 맞는 금융 용어만 밑줄로 표시합니다. 흐름도 보기 / DART 기업정보 버튼은 그대로 유지됩니다.

### 금융 이해도 점수 산정 방식
`점수 = min(100, 총 읽은 기사 수 × 5 + 총 익힌 용어 수 × 2)` 로 간단히 계산하고, 점수 구간에 따라 4단계 레벨(금융 입문자 → 초보 투자자 → 탐색가 → 고수)로 표시합니다. "취약분야"는 지금까지 설명이 필요했던 용어들을 카테고리별로 집계해 가장 자주 등장한 분야를 보여줍니다 (자주 막힌다 = 더 익혀야 할 분야). 계산 로직은 `services/literacy.js`에 있습니다.

## 4. 참고 / 한계

### 이번 업데이트 (로그인 · 실제 가입자 기준 전국 순위)
- **회원가입/로그인**: 아이디+비밀번호로 가입(`bcryptjs`로 해시 저장), 로그인하면 토큰 발급 → 브라우저 `localStorage`에 저장 → 이후 모든 API 요청에 `Authorization: Bearer <토큰>`으로 인증.
- **데이터 완전 분리**: 이제 모든 읽기 이력·저장한 기사·이해도 점수·프로필이 로그인한 사용자별로 `data/users/<userId>.json`에 따로 저장됩니다. DART 조회, 오늘의 핫 기사만 로그인 없이도 접근 가능(공용 데이터라 개인화가 필요 없음).
- **전국 순위(`/api/leaderboard`)**: 이 서버에 **실제로 가입된 사용자들**의 진짜 점수를 계산해서 순위를 매깁니다. 가짜 사용자나 추정치는 전혀 없습니다.

⚠️ **꼭 알아두셔야 할 점**: 지금처럼 `npm start`로 본인 PC에서만 띄우면, 그 서버에 가입할 수 있는 사람은 사실상 본인(그리고 같은 네트워크에 있는 사람)뿐이라 "전국 순위"가 통계적으로 의미 있으려면 **이 서버를 실제로 여러 사람이 접속 가능한 곳에 배포**해야 해요 (예: Render, Railway, 개인 클라우드 서버 등에 올리고 도메인을 공유). 배포 자체는 이 프로젝트 범위 밖이라 여기서 해드리지는 못했지만, 코드는 이미 "여러 사용자가 각자 가입해서 실제 경쟁"하는 구조로 완성되어 있어서, 배포만 하면 바로 진짜 전국 순위가 쌓이기 시작합니다.

### 이번 업데이트 (전면 UI 개편 + 마이페이지 + 학습현황 대시보드)
- **테마 전면 교체**: 네이비(#1B2044) + 크림(#F4F2EB) 배경 + 화이트 카드 + 컬러 태그 톤으로 전체 재구성.
- **온보딩**: 좌측 네이비 소개 패널 + 우측 2단계 폼(이해수준 라디오 + 관심분야 태그, "더보기"로 추가 태그 노출)의 스플릿 레이아웃으로 변경.
- **마이페이지 신설**: 프로필 카드(가입일·이해수준·관심분야), 저장한 기사(카테고리 필터), 최근 조회한 금융상품을 한 곳에서 확인. 기사 화면의 "☆ 저장" 버튼으로 북마크.
- **내 학습현황 신설**: 레벨 링(다음 레벨까지 남은 포인트), 연속 학습일수, 누적 용어, 날짜별 점수 추이 꺾은선 그래프(SVG 직접 렌더링), 카테고리별 학습 분포 바, 최근 학습한 용어 태그.
  - ⚠️ 정직하게 밝히면: "이해도 퀴즈 횟수"나 "전국 상위 %"처럼 다른 사용자와 비교하거나 퀴즈 기능이 필요한 지표는 실제로 구현되어 있지 않아 넣지 않았습니다(가짜 숫자를 보여주고 싶지 않았어요). 지금 나오는 모든 수치는 이 기기에 저장된 실제 읽기 이력 기반의 진짜 계산값입니다.
- **스마트 통역가 사이드 패널**: 기존 호버 툴팁은 그대로 유지하면서, 기사 오른쪽에 감지된 용어 전체 목록을 보여주는 패널을 추가했습니다. 용어를 클릭하면 초급/중급/고급 탭으로 즉시 난이도를 바꿔가며 볼 수 있고, "✓ 이해했어요"를 누르면 학습 완료로 기록됩니다 (같은 LLM 호출 안에서 세 난이도 설명을 한 번에 받아오므로 탭 전환 시 추가 API 호출이 없습니다).

### DART가 계속 안 될 때 — 터미널에서 바로 진단하기
브라우저까지 안 가고 터미널에서 바로 DART 연동만 따로 테스트할 수 있어요:
```bash
cd finance-reader
node scripts/test-dart.js 삼성전자
```
- `DART_API_KEY 설정 여부: 없음`이 뜨면 `.env`에 키가 안 들어간 것 → `.env` 파일에 `DART_API_KEY=발급받은키` 추가
- `등록되지 않은 키` 에러 → opendart.fss.or.kr에서 키를 다시 확인하거나 재발급 (새로 발급한 키는 승인까지 시간이 걸릴 수 있음)
- 타임아웃/네트워크 에러 → 인터넷 연결이나 회사·학교 네트워크의 방화벽 확인
- `회사를 찾지 못했습니다`가 뜨면 corpCode 다운로드 자체는 성공한 것이라, 회사명을 다르게 입력해서(`node scripts/test-dart.js SK하이닉스`) 다시 시도해보세요.

이 스크립트가 성공하면 앱에서도 정상 동작해야 합니다. 실패한다면 여기서 나오는 에러 메시지가 정확한 원인이에요.

### 이번 업데이트 (용어 중복 제거 / 원문 추출 개선 / 기업별 DART 버튼 / 상품 추천)
- **중복 용어**: 같은 용어가 기사에 여러 번 나와도 처음 등장할 때 한 번만 밑줄+설명이 붙습니다 (`public/app.js`의 `highlightTerms`가 `seenTerms` Set으로 추적).
- **원문 추출 엔진 교체**: 사이트별 셀렉터 방식 대신, 브라우저 "읽기 모드"와 같은 원리인 [Readability](https://github.com/mozilla/readability) 라이브러리를 1차로 사용하고, 실패 시에만 기존 셀렉터 방식으로 폴백합니다. 훨씬 다양한 뉴스 사이트에서 원문을 안정적으로 가져와요.
- **기업별 DART 버튼**: 기사에 여러 기업이 언급되면 드롭다운 대신 "삼성전자 DART", "SK하이닉스 DART"처럼 기업마다 버튼이 따로 생깁니다. DART에서 기업을 못 찾으면 정식 명칭을 직접 입력해 재조회할 수 있는 입력창이 뜹니다.
- **버튼 위치**: 흐름도 보기 / DART 버튼이 기사 본문 아래로 이동했습니다.
- **iM뱅크 상품 추천**: 기사에서 뽑힌 용어들을 카테고리로 집계해 가장 관련 있는 분야를 정하고, 그 분야와 어울리는 iM뱅크 상품 "유형"을 기사 아래에 보여줍니다. ⚠️ 이는 실시간 상품/금리 정보가 아니라 참고용 예시이며, 링크는 검증된 iM뱅크 공식 메인 페이지로만 연결됩니다(구체적인 상품 페이지 딥링크는 자주 바뀌어 깨질 수 있어 사용하지 않았습니다). 실제 조건은 반드시 iM뱅크 공식 채널에서 확인해야 합니다.

- 기사 본문 추출은 일반적인 뉴스 사이트 구조(article, #dic_area 등)를 기준으로 만들었고, `<br>`/`<p>` 구조를 살려 **원문 문단을 그대로** 가져옵니다(요약이나 재구성 없이, 용어에만 밑줄이 붙어요). 유료 구독 기사나 특이한 구조의 사이트는 추출이 안 될 수 있습니다 (`services/articleExtractor.js`의 `CONTENT_SELECTORS`에 셀렉터를 추가하면 됩니다).
- **난이도별 용어 선택**: 초급은 기본 용어(금리, ETF 등)까지 전부 설명하고, 중급은 그런 기초 용어는 건너뛰고 한 단계 더 들어간 용어만, 고급은 업계 상식(ETF, 레버리지, PER 등)은 아예 설명하지 않고 법률/회계/구조화상품처럼 정말 낯선 것만 골라 설명하도록 프롬프트에 명시했습니다 (`services/llm.js`의 `LEVEL_CONFIG`).
- DART의 기업 고유번호 목록(corpCode)은 최초 조회 시 1회 다운로드해 `data/corpCode.json`에 캐싱합니다(파일 크기가 커서 최초 1회는 최대 1분 정도 걸릴 수 있어요). 이 파일을 지우면 다시 받아옵니다.
- **"AI 추천"과 "오늘의 핫 기사"**는 실제 네이버 뉴스 검색 결과를 서버에서 스크레이핑해 제목/썸네일/언론사와 함께 보여주고, 클릭하면 그 기사를 바로 앱 안에서 분석해서 보여줍니다(새 탭으로 나가지 않음). 다만 이는 비공식 스크레이핑이라:
  - 네이버가 마크업(class명)을 바꾸면 `services/newsFeed.js`의 셀렉터를 손봐야 할 수 있어요.
  - 네이버가 서버 IP를 봇으로 판단해 일시적으로 403을 줄 수 있어요 — 이 경우 핫 기사는 자동으로 구글 뉴스 RSS(썸네일 없음) → 예시 데이터 순으로 대체되고, 추천은 텍스트만 있는 카드로 대체됩니다. 짧은 시간에 너무 많이 새로고침하면 이 현상이 더 잘 나타날 수 있어요.
- 모든 API 호출은 서버(`server.js`)에서 이루어지므로 API 키가 브라우저에 노출되지 않습니다.

## 5. 커스터마이징 힌트

- 난이도별 설명 톤/용어 선택 기준은 `services/llm.js`의 `LEVEL_CONFIG`에서 수정
- 디자인 토큰(색상/폰트)은 `public/style.css` 상단 `:root` 변수에서 수정
- 흐름도 레이아웃/글자 크기는 `public/app.js`의 `renderFlowSVG` 함수와 `.flow-node text` / `.flow-edge-label` CSS
- 뉴스 카드 스크레이핑 셀렉터는 `services/newsFeed.js`의 `CARD_SELECTORS`
